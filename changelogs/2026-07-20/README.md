# Changelog batch — 2026-07-20 (agent gist)

Quick orientation for anyone (human or agent) touching this folder. **Read this
before editing anything here so no work is duplicated or overstepped.**

## What this folder is

The 2026-07-20 release batch for the **Admin Changelog** (`changelog_entries`
table). It captures every feature committed on **2026-07-20** — PRs **#217**,
**#219**, **#220**, **#221** and **#222**. (Several of these merged to `main`
just after midnight on the 21st, but the commits are all dated the 20th.)

| File | Purpose |
| --- | --- |
| `2026-07-20-changelog-migration.sql` | Idempotent `INSERT`s that add this batch's rows to `changelog_entries`. Guarded per-title with `WHERE NOT EXISTS`, so it is safe to re-run and never duplicates. |
| `README.md` | This gist. |

   OFF by default; prefilled from the global fee, editable per invoice only.

   orders through Pack and Ship, with stock decrement preserved.
5. **Fulfillment queue — Product-label badge & bulk remove/restore**

   multi-select + bulk remove/restore, card layout fix.
6. **Invoices — Never save 100%-discounted lines to customer pricing**
   (PR #220) — excludes giveaway lines from the "save prices to customer" flow.

## Guardrails — do NOT overstep

- **This SQL is append-only and idempotent.** To add a NEW entry, add another
  `INSERT … SELECT … WHERE NOT EXISTS` block. **Do not edit or delete existing
  blocks** — entries are matched by `title` + `author = 'Engineering'`;
  changing a title creates a duplicate on the next run instead of updating.
- **Do not touch UI-authored entries.** Rows created through the Admin Changelog
  page are never matched by these guards; leave them alone.
- **This is NOT the base seed.** The table + schema come from
  `aminocan/changelog-migration.sql`; the historical backfill lives in
  `aminocan/changelog-append-migration.sql` (generated by
  `scripts/gen-changelog-seed.mjs`). **Do not hand-edit those generated files** —
  regenerate them from the `aminocan/changelogs/*.md` write-ups instead.
- **Feature-code DB migrations are separate.** Only the label preference needs a
  schema change (`customer-default-with-labels-migration.sql`, adds
  `customers.default_with_labels`). The rest are code-only. This changelog
  migration only writes release-notes rows — it does **not** apply any feature
  schema.

## Run order

1. `aminocan/changelog-migration.sql` — creates the table (once).
2. `aminocan/customer-default-with-labels-migration.sql` — label-preference
   column (feature schema; ship with PR #222).
3. `aminocan/changelogs/2026-07-20/2026-07-20-changelog-migration.sql` — this
   batch's changelog rows.

Run each in the Supabase SQL editor. All are idempotent.
