**Date:** 2026-07-08

**Migrations:**

## Summary

Added a centralized **Admin Changelog** interface: a chronological timeline of
update cards grouped by date that keeps the whole team aligned on platform
changes. It doubles as an internal release-notes and documentation hub, with
search, category/author/impact filters, a calendar for date navigation, and a
detail drawer for full markdown write-ups.

## Migration (run before deploying)

`changelog-migration.sql` creates the `changelog_entries` table (idempotent),
its indexes, an `updated_at` trigger, and an admin/assistant RLS **read**
policy. Writes go through the service-role key in the API routes, so there is no
client write policy. The first time it runs (only when the table is empty) it
**seeds 26 entries generated from the project's own `aminocan/changelogs/`
write-ups**, so the timeline ships pre-filled with real history instead of a
blank slate.

The seed block is generated by `scripts/gen-changelog-seed.mjs` — a
dependency-free Node script that reads each markdown write-up, extracts the
title/summary/body, attaches curated category/impact/tags/affected-areas, and
emits the rows using Postgres dollar-quoting (`$cl$…$cl$`) so arbitrary markdown
needs no escaping. Re-run it after editing the write-ups; don't hand-edit the
generated seed:

```
cd aminocan && node scripts/gen-changelog-seed.mjs
```

Columns: `category`, `title`, `summary`, `body` (markdown), `author`, `version`,
`impact` (`critical|major|minor`), `tags[]`, `affected_areas[]`, `links` (jsonb
`[{label,url}]`), `entry_date` (the timestamp the entry is grouped/dated by —
editable so entries can be backdated), `created_by`, timestamps.

### Category re-categorization patch

The seeded entries were initially all categorized `feature`/`ui`/`bugfix`/
`security`, which left the **Admin** and **Storefront** category filters empty
(that context lived in `affected_areas`, not `category`). The seed was re-mapped
to a useful spread — **admin 11, storefront 7, ui 3, feature 3, bugfix 1,
security 1**.

Because the base seed only fills an empty table (`WHERE NOT EXISTS`), it can't
fix rows that were already inserted. `changelog-recategorize-migration.sql`
patches existing databases with idempotent `UPDATE`s matched by title + author
(`Engineering`), so hand-authored entries are never touched. Fresh installs get
the correct categories from `changelog-migration.sql` and don't need the patch.
Both SQL files are generated by `scripts/gen-changelog-seed.mjs`.

## Interface

- **Route:** `/admin/changelog` (new nav item, `History` icon). Visible to
  admin/assistant; affiliates cannot access it (default page-permission rules).
- **Header:** full-text search (title/summary/body/tags/areas/author) and a
  **New Changelog** button (admins only).
- **Sidebar filters:**
  - **Calendar** — month grid; days with entries show a bronze dot; clicking a
    day filters the timeline to that date (click again / "Clear" to reset).
  - **Categories** — multi-select list, each with its badge colour.
  - **Author** — dropdown built from the authors present in the data.
  - **Importance** — All / Critical / Major / Minor.
  - A **Clear all filters** button appears when any filter is active. On mobile
    the sidebar collapses behind a **Filters** toggle with an active-count badge.
- **Timeline:** entries are paginated (10/page) then grouped by day with a date
  heading and per-day update count. Each **card** shows the category badge,
  impact + version chips, time, title, summary, affected areas, tags, author,
  and a **Read More** action.
- **Detail drawer:** Read More slides in a right-hand drawer (Escape / backdrop
  to close) with the full **markdown** body, affected areas, tags and related
  links — the timeline stays in context behind it.
- **Create / Edit / Delete:** admins get a form modal (category, title, summary,
  markdown details, author, version, impact, date/time, comma-separated tags &
  affected areas, and repeatable related links) and a delete confirmation.
  Assistants are read-only.
- **Create Report:** a header button opens a popup with a calendar; pick a day
  and get a **copyable list of that day's update titles** plus a **shareable
  link** to the changelog **pre-filtered to that day**, and an *Open filtered
  view* action. The page honors a `?date=YYYY-MM-DD` deep link (and mirrors the
  calendar filter into the URL) so those links open straight to the right day.

## Categories & colours

Admin (blue), Storefront (emerald), Feature (purple), Patch (gray), Bug Fix
(red), Performance (cyan), Security (orange), API (indigo), Database (amber), UI
(pink), Mobile (teal) — a distinct badge per category for fast scanning.

## Implementation notes

- Category/impact presentation metadata and the client API live in
  `lib/admin/changelog.ts`; DB types were added to `lib/supabase.ts`.
- API routes (`app/api/admin/changelog/route.ts` and `.../[id]/route.ts`) mirror
  the existing admin CRUD pattern: bearer-token role check, `canCreate`/`canEdit`
  /`canDelete` gating, input normalization, and audit-log writes via
  `logAuditServer`.
- A dependency-free markdown renderer (`_components/Markdown.tsx`) handles
  headings, lists, bold/italic/code and links without injecting raw HTML.
- Reused shared `groupByDay`/`localDayKey` (`lib/dayGroups.ts`), the shared
  `Pagination` and `ConfirmDeleteDialog` components. Added a `slide-in-right`
  animation to `tailwind.config.ts` for the drawer.
