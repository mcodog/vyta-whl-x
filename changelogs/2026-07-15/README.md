## Guardrails — do NOT overstep

- **This SQL is append-only and idempotent.** To add a NEW entry, add another
  `INSERT … SELECT … WHERE NOT EXISTS` block. **Do not edit or delete existing
  blocks** — entries are matched by `title` + `author = 'Engineering'`;
  changing a title creates a duplicate on the next run instead of updating.
- **Do not touch UI-authored entries.** Rows created through the Admin Changelog
  page are never matched by these guards; leave them alone.
- **This is NOT the base seed.** The table + schema come from
  `aminocan/changelog-migration.sql`; the historical backfill lives in
  `aminocan/changelog-append-migration.sql` (generated by
  `scripts/gen-changelog-seed.mjs`). **Do not hand-edit those generated files** —
  regenerate them from the `aminocan/changelogs/*.md` write-ups instead.
- **Feature-code DB migrations are separate.** The alternate-email feature needs
  `customer-alternate-email-migration.sql` (already in the repo). The rest of
  this batch is code-only. This changelog migration only writes release-notes
  rows — it does **not** apply any feature schema.

## Run order

1. `aminocan/changelog-migration.sql` — creates the table (once).
2. `aminocan/customer-alternate-email-migration.sql` — feature schema for the
   alternate-email column (ship with PR #191).
3. `aminocan/changelogs/2026-07-15/2026-07-15-changelog-migration.sql` — this
   batch's changelog rows.

Run each in the Supabase SQL editor. All are idempotent.
